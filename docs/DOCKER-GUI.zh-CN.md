# NAS Display：按飞牛 Compose 界面部署

此包面向铁牛 NAS（Centerm Zero1 pro / IT8613 / Debian），按飞牛的 Docker → Compose → 创建项目 → 构建与启动流程准备。安装不需要 SSH、NAS 终端、DEB 或 FPK。铁牛具体菜单名称可能不同；目标铁牛界面与硬件加载尚未实测，本文不是实机验收记录。

## 1. 解压并上传整个目录

在电脑上解压 `NAS-Display-Compose-1.5.2-amd64.zip`。通过 NAS 文件管理器，将整个解压目录上传到持久存储位置，例如自己创建的 `docker/nas-display` 目录。以界面显示的实际目录为准，不手写猜测的 `/vol...` 路径。

目录内应直接有：

- `docker-compose.yml`：创建项目时使用的编排。
- `Dockerfile`：本地镜像组装说明。
- `runtime.tar.gz`：已编译好的应用、运行环境、IT8613 驱动与对应源码。
- `.dockerignore`：限定构建读取的文件范围，上传时保留隐藏文件。
- README、IMAGE.json、SHA256SUMS.txt：说明、来源和校验信息。

不要解开 `runtime.tar.gz`，不要将此文件或 ZIP 填到“添加下载链接”。它们不是镜像仓库地址。这个包也不是 `docker load` 镜像包。

## 2. Docker → Compose → 创建项目

在飞牛网页打开 Docker，进入 Compose，点击创建项目：

1. 项目名称填写 `nas-display`。
2. 项目路径选择刚上传的目录，确保该目录下直接有 Dockerfile 和 runtime.tar.gz，没有多套一层文件夹。
3. 将包内 `docker-compose.yml` 的全文放入 YAML 编辑框；若界面支持选择现有编排文件，也可以直接选择它。
4. 先不要启动，完成下一步的初始密码设置。

项目路径是构建读取本地文件的位置，不要选择空目录或临时目录。以后更新保持相同项目名称，以保留数据卷。

## 3. 设置自己的初始密码

在 YAML 的 `nas-display` → `environment` 内找到：

```yaml
      NAS_DISPLAY_ADMIN_PASSWORD: ${NAS_DISPLAY_ADMIN_PASSWORD:?请填写初始登录密码}
```

把冒号右侧的整段 `${...}` 替换成自己设置的密码，并用单引号包住。建议初始密码使用至少 12 位随机英文字母和数字，避免 YAML 与 Compose 特殊字符转义问题。不要使用文档占位内容作为密码。

不填写密码时，编排会报告“请填写初始登录密码”，不会静默生成一个需要终端读取的密码。该设置只用于全新实例，已有实例的密码不会被覆盖。

密码会保留在编排和容器配置中。首次登录后可在“账户设置”修改密码；再从编排删除 `NAS_DISPLAY_ADMIN_PASSWORD` 这一行并应用配置，保留数据卷即可。

如端口 8787 已占用，可以直接把同一区域的 `NAS_DISPLAY_PORT: 8787` 改为其他空闲端口。

## 4. 构建，然后启动

保存项目，通过 Compose 页的构建、启动按钮完成部署；有“创建项目后立即启动”选项的版本，可在设置好密码后使用。

这里的“构建”只是将包内已经编译好的运行环境组装成镜像：使用 `FROM scratch` 和本地压缩包，不下载基础镜像，不联网安装依赖，也不在 NAS 编译驱动。四个服务均已配置本地构建，首次启动不需要先导入镜像，也不依赖任何镜像仓库。镜像层由引擎共享，四个服务不会各占用一套完整运行环境的磁盘空间。

项目应包含四个容器：

| 服务 | 用途 |
|---|---|
| nas-display | 网页、数据采集、向屏幕发送数据 |
| driver | 检查并尝试加载匹配内核的 IT8613 驱动 |
| fans | 风扇通道和转速曲线控制 |
| smart | 硬盘健康及温度采集 |

这些容器的入口、挂载和权限已在编排中配置，保持原样即可。不要仅启动网页容器就认为驱动和调速已经部署完成。

## 5. 打开网页

访问 `http://NAS的IP:8787`，输入步骤 3 设置的密码，无需用户名。如修改了端口，使用修改后的端口。

在“屏幕与采集”选择 Wi-Fi UDP，填写屏幕显示的 IPv4 地址，端口 44445，保存并启用发送。屏幕须使用免配对固件；不连接屏幕也能使用监控网页。

在网页“硬件准备”查看驱动检查结果，并到风扇页面确认通道。内置驱动只适配 `6.1.0-39-amd64` / x86_64 与目标主板；如果内核不匹配、签名限制或权限不足，会显示原因，其他监控仍可运行。模块加载成功不等于已经验证实体风扇响应。

## 查看日志、停止与更新

通过 Docker 的容器详情或运行日志查看 nas-display、driver、fans、smart 的输出，无需容器终端。正常停止项目时，fans 会尝试恢复接管前的模式；重新启动恢复已保存曲线。停止 driver 不卸载宿主机模块。

更新时停止原项目，上传新版包覆盖程序文件，保留原项目名称与用户填写的配置，再从界面重新构建和启动。不要勾选删除数据卷或清除应用数据。

## 界面报错的判断

- **找不到 Dockerfile / runtime.tar.gz**：项目路径选错，或上传文件不完整。
- **提示填写初始登录密码**：还没有替换步骤 3 的 `${...}`。
- **请求拉取 nas-display 镜像**：使用了旧离线镜像包的 compose.yaml；本包使用 docker-compose.yml，四个服务都有 build，没有 image 仓库地址。
- **不支持 build / 权限字段 / 健康检查依赖**：当前铁牛界面没有完整支持本编排，保留报错供适配；不通过删除驱动所需字段来假装部署完成。
- **已有应用、风扇管理服务在控制同一硬件**：先从相应应用界面停止控制，避免两个程序同时写风扇。
