# 传感器与温度来源

网页与 S3 的 CPU 温度统一由「屏幕与采集 → CPU 温度来源」决定。保存后下一次刷新生效，屏幕不用重新烧录。与 btop / lm-sensors 对比时，以同一个驱动、同一个传感器标签为准；标准 top 不提供 CPU 温度，其他软件的 Auto 选择也不一定相同。

## 自动规则

- Intel coretemp：优先 Package id / Physical id，无封装通道时使用最热核心。
- AMD k10temp / zenpower：优先 Tdie，其次 Tctl，二者均不可用才回退到该驱动的有效温度通道。多插槽取各插槽候选值的最高值。
- 上述驱动无可用温度时，只使用明确 CPU 标签的 thermal zone；不把显卡、硬盘、ACPI 或任意主板通道当成 CPU。
- 不设置型号专属减温差或把几个 CCD 的平均值冒充封装温度。旧配置升级后仍为自动。

## 与其他监控软件一致

在两边选择相同的 `驱动 / 标签`。例如 Ryzen 9 9950X：

| 选择 | 含义 |
|---|---|
| k10temp / Tctl | CPU 温控读数，默认使用 |
| k10temp / Tccd1、Tccd2 | 各 CCD 芯粒温度，不能与封装读数混称 |
| asusec / CPU Package | 主板提供的 CPU Package 通道 |
| asusec / CPU、nct6799 / CPUTIN | 主板标记的 CPU 通道，其测点与校准由主板决定 |

在 btop 的 CPU 设置中选同名通道即可。需要对比 btop 时，先确认它实际选择的通道，再在 NAS Display 中选择同一通道；数值接近本身不是来源相同的证据。不同采样时刻仍会有小幅差异。

网页在 CPU 卡片下方显示实际使用的驱动与标签。手动选中的通道丢失或不可读时显示 `--` 并提示重新选择，不会静默切换成另一个温度。hwmon 编号变化不影响硬件路径相同的通道；更换主板或 CPU 后可重新选择「自动」。


## GPU、硬盘与 SYS

GPU 依实际设备识别 NVIDIA、AMD 或 Intel。NVIDIA 使用 nvidia-smi；AMD 等驱动使用可用的忙碌率节点；Intel i915 在可用时使用原生 PMU，引擎最忙值包含视频编解码，不是简单按引擎相加。xe 不提供该 PMU 后端。温度和占用率不可读时保留缺失，不使用 CPU 温度、频率比或零值代替。

NVMe 温度优先使用内核暴露的设备传感器；SATA、SCSI 和支持 SMART 的 USB 硬盘由 smartctl 定时读取缓存。休眠、不可读、不支持、采集等待和缓存过期分别显示，不为了刷新界面强行唤醒磁盘。USB 桥接芯片可能不支持 SMART 透传。

SYS 来源在“屏幕与采集”选择，使用真实驱动和通道标识。没有可信标签时不凭 temp1/temp2 推断物理位置；负值或无效值不展示成正常温度。读取风扇 fanN_input 得到 RPM，0 RPM 与不可读分别处理，报警保留。

CPU 显示来源与每条风扇曲线的温度来源是独立设置。曲线不使用磁盘或 GPU 缓存温度。运行条件和当前自动规则以网页显示的来源及实际驱动接口为准。
