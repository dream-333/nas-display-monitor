# 风扇调速与温度曲线

开发者 / 发布者：Dream。网页端口仍为 8787，旧配置与账号保留。更新上位机即可，S3 固件无需重新烧录。

## 自动与手动

网页显示实际转速 RPM 和 0–100% 控制输出。手动模式填写整数百分比并点击应用；自动模式不将硬件自动起始参数冒充实时占空比。0% 允许停转，100% 请求最大输出，不能据此设定精确目标 RPM。

按内核提供的 hwmon 接口识别控制器，不按主板品牌猜测。EC/WMI 可能只提供转速；读取成功不表示有可写控制接口。Nuvoton、Winbond、ITE 等控制器需要系统有匹配驱动和当前适配支持。ProArt X870E 的用户反馈是在加载 nct6775 后出现 nct6799 通道，具体物理风扇对应关系仍需确认。

接管前没有可恢复自动基线的通道不猜测自动模式编号。底层的百分比到 0–255 转换与模式恢复由驱动适配层完成。

## 温度曲线使用

在运行概览的「风扇调速」选择一个已确认接线的通道，将控制方式设为「温度曲线」。选择温度源和静音 / 标准 / 性能 / 全速预设，也可拖动节点或展开「曲线节点与响应设置」输入数值。所有改动先预览，点击「应用设置」才开始控制。白点是后台上次检查的温度与实际输出，虚线是全速保护温度；实际 RPM 单独显示，百分比是控制输出，不代表最大 RPM 的线性比例。

每个风扇独立设置，2–8 个节点，可添加 / 删除；横轴为摄氏度、纵轴为 0–100% 输出。编辑温度或响应参数后标记为「自定义」。切回「自动」会退出软件曲线并恢复接管前的主板自动策略。原本处于不可恢复的手动模式、只读或未适配驱动的通道不开放曲线。

CPU 温度按驱动 / 标签识别；每条风扇曲线独立选源，不随网页 CPU 显示源改变而悄悄变更。可选择 CPU 自动、单个 CPU 通道或已发现的主板传感器（SYS / VRM 等）。显卡和磁盘缓存温度暂不作为本版控制源。

## 预设

以下为本应用的初始值，参考厂商的交互与功能，不是照搬某块主板的原厂曲线。风扇、散热器和温度测点不同，应用后需要观察温度与真实转速。

| 模式 | CPU 曲线（°C → 输出 %） | 主板温度曲线（°C → 输出 %） | 升速 / 降速延迟 |
|---|---|---|---|
| 静音 | 35→40，55→45，70→65，85→100 | 25→40，35→45，45→65，60→100 | 2 / 15 秒 |
| 标准 | 35→40，50→55，65→75，80→100 | 25→40，35→55，45→75，55→100 | 1 / 10 秒 |
| 性能 | 30→60，45→75，60→90，75→100 | 25→60，30→75，40→90，50→100 | 0 / 5 秒 |
| 全速 | 始终 100% | 始终 100% | 0 / 0 秒 |
| 自定义 | 2–8 点，温度递增、输出非递减、最后一点 100% | 同左 | 可编辑 |

默认最低输出 40%，降温回差 3°C；CPU 全速保护 85°C、主板源 60°C，均可编辑。这些是预设起点，不能作为所有 CPU/主板的统一安全温度；请根据所选传感器与硬件规格调整。曲线最低输出可设 0–100%。要在低温时输出 0%，请同时把最低输出与相应低温节点设为 0%；只把最低输出改成 0%，不会自动改变已有节点。输出 0% 表示允许停转，实际是否停转由风扇与主板决定。升温后按曲线及升速延迟正常输出，不额外增加启动加速脉冲。

线性方式在节点之间插值；阶梯方式到下一温度节点再跳变。回差作用于降温，避免临界点附近反复变速。升速延迟范围 0–10 秒、降速延迟 0–60 秒。到保护温度时跳过延迟直接请求全速。

## 后台与恢复

- 调速在独立的本地特权服务中运行，不依赖网页保持打开、S3 在线或网页采样是否暂停；网页只能发送通道 ID 与配置，不能提交硬件路径或伪造温度数值。
- 不改写 BIOS 温控曲线或电气控制类型，沿用已适配的驱动接口设置手动输出；接管前原始模式与 ITE 起始参数先写入恢复日志，再进行硬件写入。
- 最多同时运行 8 个通道，顺序轮询。空闲通道检查间隔至少 2 秒；驱动每次改速有约 1.6 秒的读回验证，多通道同时改速会增加轮询延迟。配置的升降速延迟在实际轮询时判断，不是硬实时保证。
- 温度源不可读、负值、越界、丢失或 CPU 自动选择的实际传感器集合改变时，停止该软件曲线并尝试恢复主板自动。不会用 0°C 替代失败，也不会自动切换到较冷测点继续调速。
- 曲线目标为 0% 时，零转速与对应低速报警视为正常停转，不会自动拉到全速。实际输出与曲线目标均大于 0% 后，转速反馈连续为零达到 10 秒则请求全速；非零转速反馈下的风扇报警也会触发保护。普通主板反馈为同编号风扇输入，必须确认物理对应关系；无反馈时不能做停转检测。
- 检测到其他程序改变当前输出 / 模式时停止曲线，不持续抢写；请勿同时启用其他调速程序。
- 服务正常停止时尝试恢复接管前模式；异常退出后 systemd 重启服务，先依据本次开机的日志恢复。新增 30 秒进程看门狗；卡住后由 systemd 终止并重启。恢复失败保留日志并报错，不能保证损坏/断开的硬件可恢复。
- **已应用的曲线保存为启用状态；关闭网页继续调速，服务重启或重启主机后自动恢复曲线。** 启动时核对控制接口与温度源，按当时温度计算输出，不重放关机前的固定输出值。切回自动 / 手动模式会取消该曲线自启动；未点击应用的网页改动不会保存。
- fnOS 启动时先保持网页可用，等待驱动准备任务结束后再启动风扇服务并恢复曲线，避免驱动尚未加载时误判通道不可用。
- 服务停止时恢复接管前的主板模式和参数，不重置 BIOS。重启服务的停止阶段同样会短暂归还主板控制，启动后自动接回已启用曲线。单独停止服务时主板继续接管；以后再次启动服务则恢复曲线。
- 主机重新启动后沿用本次启动的 BIOS 自动参数作为新恢复基准，不写回上一次开机的快照。温度源缺失 / 改变或控制接口无法恢复时，保留主板控制并显示失败原因，需要检查后重新应用；一个通道失败不阻止其他有效曲线恢复。
- 从 1.5.0 升级时，旧文件只有曲线配置，没有启用标记，因此保留为草稿，需要在升级后应用一次；之后重启自动继续。正常停止保留启用状态；传感器 / 控制故障退出或检测到其他程序改值时停用该曲线，避免重启后反复接管。
