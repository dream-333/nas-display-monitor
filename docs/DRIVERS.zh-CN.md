# fnOS 驱动准备

开发者：**Dream** · 发布者：**Dream**

飞牛应用支持后台驱动准备。网页地址保持 `http://NAS的IP:8787`，没有连接下位机也可实时查看主机状态，屏幕固件无需更新。

## 全新飞牛怎么装

1. 应用中心手动安装 `NAS-Display-fnOS-1.5.2-x86.fpk`。按提示安装官方 Python 3.12 运行环境。
2. 设置至少 8 个字符的管理员密码，风扇驱动策略保留默认「自动准备已验证主板的驱动」。
3. 启动 NAS Display，点击图标进入网页。网页先启动，硬件准备在后台进行；「硬件准备」区域显示当前阶段和结果。
4. 已有可读转速接口时直接沿用现有驱动。**Centerm Zero1 pro** 缺少接口且没有已加载的 it87 时，自动准备编译工具、当前内核头文件及所需版本的编译器，再通过 DKMS 编译随包的 IT8613 驱动。
5. 安装成功后自动验证转速，并启用驱动开机加载；网页下一轮采样就能发现新风扇。SYS 仍按传感器标签或用户选择的通道显示，不凭空确定 temp2 的物理位置。

**这不是对所有 fnOS / 主板的无条件保证。** 全新系统需要联网，系统软件源必须提供匹配当前内核的完整头文件和编译工具。缺少头文件、依赖下载失败、签名限制、已有驱动冲突或未验证主板时，网页会说明原因，其余监控继续运行。

## 策略与重试

飞牛应用设置 →「密码与硬件准备」：

- 自动准备：已有接口不重装；仅对已验证的主板尝试随包驱动。
- 仅使用现有驱动：不安装新驱动。

应用运行时保存配置可再次启动检查；已经有准备任务在运行时不会重复启动。应用重启会重新检查，因此 DKMS 在内核更新后未能构建时，也会重新检查当前内核条件。

策略不会卸载已安装的驱动。关闭或更新应用时，正在进行的包管理/编译阶段会先结束，再停止；不要在系统安装依赖期间强制断电。

驱动日志：

```bash
sudo journalctl -u nas-display-fnos-hardware.service -n 100 --no-pager
```

## 从旧版本切换

- FPK：通过应用中心更新，配置及密码保留。
- Debian 版：先卸载 `sudo apt remove nas-display-host`，释放 8787 和 USB，再安装 FPK。旧 `/var/lib/nas-display-host` 会保留，但配置与密码不会自动迁移；可在网页导入旧 `config.json`。
- 已装过 IT8613 驱动：不必重复安装，程序会先检查可用接口。
- 卸载 FPK 不卸载独立的 DKMS 驱动、不删除驱动源码，也不卸载编译依赖；驱动可能同时被其他监控软件使用。

## 实现边界

- 驱动源码固定为 frankcrawford/it87 `a904dd88b295a1bd4eeb47af523d8fad1e566a9f`，版本 `nasdisplay-a904dd88`，与之前 NAS 实测使用的驱动一致，随包包含 GPL 许可和完整源码；不提供跨内核复用的预编译 ko。
- 不运行 sensors-detect 的广泛硬件扫描，不尝试未知主板驱动，不使用 force_id、ACPI 资源冲突绕过或禁用 Secure Boot。
- 不执行风扇脉冲测试，不修改 PWM、风扇模式或温控曲线。正常内核驱动加载会初始化传感器硬件，不能将驱动安装称为纯只读。
- 网页以专用非 root 用户运行，只读取状态；没有从网页传入任意命令、模块名或安装包名的接口。单独的 root 生命周期服务负责固定的依赖和驱动准备。
- 编译工具从系统已配置的软件源安装，不修改系统软件源，不执行 autoremove、不强制替换其他 it87 版本。

## 验证边界

自动化测试使用临时 sysfs 和模拟命令，覆盖已有驱动、0 RPM、未知主板、Secure Boot、错误头文件、源码损坏、依赖失败、驱动冲突和安装后验证。开发机没有执行 apt 安装、模块加载或风扇控制。

FPK 用官方 fnpack 打包；检查了服务配置、脚本语法、载荷摘要和包内程序的独立网页运行。**仍需在全新 fnOS 实机验证整个应用中心安装及自动依赖安装流程**；之前的 IT8613 驱动本体已由用户在 NAS 上编译加载成功。
